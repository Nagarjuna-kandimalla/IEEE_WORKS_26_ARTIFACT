# Component: data and cohorts

This document identifies every task population and explains where it enters
the experiments. Do not compare row counts from different stages without
checking which population is being used.

## Data layers

| Layer | Purpose | Location |
|---|---|---|
| Workflow inputs | Execute RQ1 workflows | `WORKFLOWS/<workflow>/data`, plus downloaded files under an uncommitted data root |
| Static task manifests | Match data-parallel tasks to known static properties | `WORKFLOWS/<workflow>/data/static_task_manifest_*.tsv` |
| RQ1 run outputs | Trace, audit, timing, and normalized task observations | generated under `$RUN_ROOT/<workflow>/exp0|exp1|exp2` |
| RQ2 cohort | Offline causal allocation experiment | `DATA/RQ2/camp_ml_cohort_33516.csv.gz` |
| RQ2 split manifests | Fixed chronological development/holdout membership | `SCRIPTS/RQ2/data/split_manifests` and `variance_manifests` |
| RQ3 cohort | Fair CAMP/Sizey comparison subset | generated by `SCRIPTS/RQ3/harness/scripts/prepare_data.py` |
| RQ4 frozen inputs | Gate fitting and selective-audit evaluation | `DATA/RQ4/inputs/seed_1996` |
| Final tables | Inputs to retained figures | `RESULTS/RQ*/csv` |

## Workflow input datasets

### GATK

The custom GATK workflow uses the included synthetic compressed reference,
20 sample definitions, and 25 interval definitions. The Cartesian task design
creates 500 HaplotypeCaller tasks. The workflow generates paired FASTQs from
fixed seeds. No external biological dataset is required.

Relevant files:

```text
WORKFLOWS/gatk/data/hg38_synthetic.fa.gz
WORKFLOWS/gatk/data/samples_20.tsv
WORKFLOWS/gatk/data/intervals_25.tsv
WORKFLOWS/gatk/data/static_task_manifest_500.tsv
```

### Minimap2

The custom Minimap2 workflow generates its synthetic reference, annotations,
1,500-window plan, and ONT-style reads with included scripts and fixed seeds.
The workflow normally performs generation automatically.

Relevant files:

```text
WORKFLOWS/minimap2/data/window_manifest_1500.tsv
WORKFLOWS/minimap2/data/static_task_manifest_6003.tsv
WORKFLOWS/minimap2/scripts/generate_reference.py
WORKFLOWS/minimap2/scripts/plan_windows.py
WORKFLOWS/minimap2/scripts/generate_window_reads.py
```

### Sarek

Sarek uses the public GIAB NA12878 30x paired whole-genome reads and 1,495
non-overlapping GRCh38 primary-chromosome intervals. The two compressed input
objects total approximately 92 GB. The workflow can stream them from S3 or use
a local samplesheet after predownload.

### Seqinspector and Viralmetagenome

Both use the same selection of 3,000 paired metagenomic WGS runs from ENA.
Their reproduction manifests record exact URLs, sizes, and MD5 values. The
6,000 FASTQ objects total approximately 46.1 GiB compressed. They can be
streamed by the supplied samplesheets or downloaded once and shared.

### Taxprofiler

Taxprofiler uses 5,998 public paired Illumina metagenomic WGS runs from ENA.
Its 11,996 FASTQ objects total approximately 146.6 GiB compressed. The
supplied manifest and HTTPS samplesheet identify the exact selection.

### Shared Kraken2 database

Seqinspector, Taxprofiler, and Viralmetagenome use the Kraken2 Standard-8
archive dated 2026-06-26. It can be staged from its URL or downloaded once and
referenced from local samplesheets/configuration. Acquisition and integrity
commands are in [`../WORKFLOWS/README.md`](../WORKFLOWS/README.md).

## RQ1 observed task rows

RQ1 begins with complete Nextflow traces. Those traces can include main
data-parallel tasks and workflow support/reporting tasks. The retained RQ1
signal table contains these row counts per mode:

| Workflow | Rows |
|---|---:|
| GATK | 500 |
| Minimap2 | 6,003 |
| Sarek | 6,012 |
| Seqinspector | 6,004 |
| Taxprofiler | 6,000 |
| Viralmetagenome | 9,003 |

The RQ1 normalizer keeps only `COMPLETED` and `CACHED` trace rows, attaches
static-manifest fields where applicable, and enriches staged input sizes. The
audit summaries are joined by task identity. GATK uses its dedicated
HaplotypeCaller metrics table.

## RQ2 matched cohort

`DATA/RQ2/camp_ml_cohort_33516.csv.gz` contains 33,516 matched logical tasks:

| Workflow | Tasks |
|---|---:|
| GATK | 500 |
| Minimap2 | 6,001 |
| Sarek | 6,012 |
| Seqinspector | 6,001 |
| Taxprofiler | 5,999 |
| Viralmetagenome | 9,003 |

The difference from the RQ1 trace counts is intentional: the offline cohort
is the validated matched population, not an unfiltered concatenation of every
trace row.

The cohort contains task identity, workflow/process/version, static and staged
input sizes, task and worker configuration, causal ordering fields, runtime,
peak RSS, successful read-return bytes, mmap page-fault bytes, and total eBPF
consumed bytes. The model loader verifies required columns and expected row,
workflow, and process counts.

Materialization converts the compressed CSV to the TSV expected by the model
programs:

```bash
.venv-rq2/bin/python SCRIPTS/RQ2/materialize_offline_data.py \
  --source DATA/RQ2/camp_ml_cohort_33516.csv.gz \
  --output DATA/RQ2/generated/canonical_matched_tasks.tsv
```

The generated TSV is working data and should not be committed.

## Chronological assignments

The primary seed-1996 allocation result uses 28,490 development tasks and
5,026 later test tasks. The six workflow manifests in
`SCRIPTS/RQ2/data/split_manifests` fix membership and replay order.

The variance experiment uses fixed manifests for five development/test
fractions:

| Split | Development | Test |
|---|---:|---:|
| 30/70 | 10,057 | 23,459 |
| 50/50 | 16,758 | 16,758 |
| 70/30 | 23,460 | 10,056 |
| 85/15 | 28,490 | 5,026 |
| 90/10 | 30,166 | 3,350 |

Each outer model seed reuses the same task membership for its split. Changing
the development fraction changes the future holdout as well as the amount of
training data; the splits are not independent random test samples.

## RQ3 matched comparison population

RQ3 derives an eligible 30,478-task primary cohort from the packaged RQ2 data
and creates matching Sizey inputs. Seed 1996 assigns 9,141 tasks to initial
training and 21,337 to replay testing. Every compared method is evaluated on
the same 21,337 logical task IDs.

The preparation program validates required source columns, filters eligible
rows, writes immutable cohort files, produces workflow-specific Sizey inputs,
and writes the shared split manifests. Its generated files live below
`SCRIPTS/RQ3/harness/data` and are working outputs.

## RQ4 frozen population

RQ4 uses the same 9,141 initial and 21,337 experiment tasks as the comparison
setting, with frozen causal features, `C-hat`, and A+P/A+P+C prediction tables.
The compressed inputs are expanded by `SCRIPTS/RQ4/prepare_inputs.py` into the
working layout expected by the evaluator. All prediction and feature tables
must align by logical task ID before the gates are evaluated.

## Data leakage boundary

The current task's peak RSS, measured consumption, runtime, and observed OOM
status are outcomes. They are allowed as training labels and retrospective
evaluation fields, but not as prelaunch features for that same task. History
is built only from completed earlier tasks, initial cross-fitting provides
out-of-fold predictions, and chronological test tasks are processed in replay
order. RQ4 likewise builds gate scores from pre-outcome fields and reveals
outcomes only for retrospective metric calculation.

## Final data products

The committed figure inputs are deliberately smaller than generated working
directories:

- RQ1: two signal/overhead CSVs plus the special Sarek timing input;
- RQ2: two compressed seed-1996 prediction tables and three aggregate CSVs;
- RQ3: `global_metrics.csv`;
- RQ4: the compressed A+P repetition table.

See [`../RESULTS/README.md`](../RESULTS/README.md) for exact paths, meanings,
and checksums.
